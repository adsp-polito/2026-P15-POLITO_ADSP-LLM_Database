db_06 - Home appliance retail stores (difficulty: Medium)
==========================================================

Domain
------
The operational database of "Casalux", an invented Italian chain of home appliance stores
(Milano, Torino, Bologna, Roma). It tracks the stores, the appliance catalogue, loyalty
customers, per-store stock and after-sales repair tickets. Prices are in EUR; all people,
brands and companies are invented and every email uses example.com.

Collections
-----------
- stores (4 docs): one document per physical store: code, name, postal address, contact
  details, opening hours, floor area, opening date and status.
- products (5 docs): the appliance catalogue: SKU, model, brand, category, list price,
  EU energy class (missing for the microwave, which has no energy label), warranty length,
  physical dimensions, launch date, active flag.
- customers (5 docs): loyalty-programme members with contact data, home store, a wishlist
  of appliances and one or more delivery addresses (with floor / elevator info that matters
  for delivering large appliances).
- inventory (5 docs): one stock record per store and product: on-hand, reserved and
  reorder quantities, aisle, last physical count.
- repair_tickets (5 docs): after-sales repair jobs: which store took the appliance in,
  which product model it is, the customer to contact, serial number, warranty status,
  reported fault, spare parts used and costs. For completed out-of-warranty tickets
  total_charged = sum(quantity x unit_cost) + labor_cost; warranty repairs charge 0.

Relationships
-------------
customers.home_store -> stores           inventory.location -> stores
customers.wishlist[] -> products         inventory.product.product_id -> products
repair_tickets.intake_store -> stores    repair_tickets.appliance -> products
repair_tickets.customer.customer_id -> customers
Every identifier is an ObjectId equal to the _id of a document in sample_documents.json.

Patterns (12 labelled paths)
----------------------------
Embedding (5):
  stores.address (object), stores.opening_hours[] (array of objects),
  products.dimensions (object), customers.addresses[] (array of objects),
  repair_tickets.parts_used[] (array of objects).
  None of these nested items is stored as a document in any collection.
Referencing (5):
  customers.home_store (single id), customers.wishlist[] (list of ids),
  inventory.location (single id), repair_tickets.intake_store (single id),
  repair_tickets.appliance (single id).
ExtendedReference (2):
  inventory.product = {product_id, sku, name, brand} copied from products, so stock lists
  show the item without a lookup;
  repair_tickets.customer = {customer_id, first_name, last_name, phone} copied from
  customers, so technicians can call the customer directly.
  The copied values equal the referenced documents and the copied fields appear nowhere
  else in the referencing collections.
Total: 5 Embedding + 5 Referencing + 2 ExtendedReference = 12 entries in ground_truth.json.

No Array, Subset or Bucket pattern is present: there are no lists of plain scalar values,
no bounded copies of child documents and no time-series groupings.

How the difficulty requirements were applied
--------------------------------------------
- Role-named identifiers (not <entity>_id): customers.home_store, inventory.location,
  repair_tickets.intake_store, repair_tickets.appliance. All identifiers are ObjectIds.
- Mixed forms: single identifiers (customers.home_store, inventory.location, ...) and a list
  of identifiers (customers.wishlist[]); single embedded objects (stores.address,
  products.dimensions) and arrays of objects (stores.opening_hours[],
  customers.addresses[], repair_tickets.parts_used[]).
- A collection with 2 patterns other than Referencing: repair_tickets has
  ExtendedReference (customer) and Embedding (parts_used[]); stores has two Embedding paths.
- No pattern nested inside another: embedded objects/arrays contain only plain fields,
  and the ExtendedReference sub-objects contain only the id plus plain copied fields.
- Arrays vary in length: opening_hours[] 3/2/2/3, wishlist[] 2/3/2/2/4,
  addresses[] 2/1/3/2/2, parts_used[] 2/1/3/2/2.
- Optional fields missing in some documents: stores.email, stores.has_click_and_collect,
  products.energy_class, customers.phone, customers.birth_date, addresses[].floor,
  addresses[].has_elevator, inventory.aisle, repair_tickets.closed_at, labor_cost,
  total_charged.
